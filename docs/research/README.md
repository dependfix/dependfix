# 调研文档规范（Research）

> 本目录存放**调研 / 研究类文档**（竞品分析、技术调研、决策依据等），
> 与 [design](../design/packages/index.md)（设计落地）和 [plan](../plan/todo.md)（规划）分离。

## 命名规范

1. **文件名必须包含日期**，格式：`{YYYY-MM-DD}-{topic-slug}.md`
   - 示例：`2026-08-04-github-token-dependabot-bug-or-design.md`
   - 日期为调研**完成日期**；topic-slug 为小写 kebab-case 主题词
2. **同一天对同一主题多次调研**（追加搜索、数据更新、结论修正）时，**追加版本后缀**：
   - `2026-08-04-github-token-audit-v2.md`
   - 规则：保留旧版本（历史决策依据），新版本用 `-v{n}`（n 从 2 起）
3. 旧版被新版完全覆盖且无决策参考价值时，可删除旧版（如 `competitive-research.md` 被 `2026-07-26-competitive-research.md` 覆盖后删除）

## 内容结构（建议）

```markdown
# {调研主题}

> 调研日期: {YYYY-MM-DD}
> 方法: {来源扫描 / 官方文档 / 交叉验证 / 本地实验}
> 结论: {一句话核心结论}

## 摘要
## 关键事实（含出处/链接）
## 交叉验证
## 结论与建议
```

## 内容处置流程

调研完成后按以下优先级处置（在调研文档末尾注明处置去向）：

1. **落地**：结论进入设计文档（`design/packages/` 或 `design/governance/`）与规划（`plan/`）
2. **保留**：作为未来决策依据（如 `2026-08-02-release-tools-comparison.md` 支撑发布方案）
3. **归档 / 删除**：被覆盖或价值已尽（如早期 `cost-estimate.md` 仅保留参考价值）

## 目录治理

- 调研文档与实现脱节时，先判断"结论是否仍有效"：有效 → 保留；无效 → 删除或更新日期版本
- 定期（阶段收尾时）检查本目录，清理无引用、无价值的旧调研
