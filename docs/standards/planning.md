# 项目规划与评估规范

## 1. 规划约束

- **阶段性聚焦**: 单个迭代核心任务控制在 5-6 项以内，超出时遵循"进一出一"。
- **功能解耦**: 新功能不破坏现有核心逻辑。
- **测试先行**: 规划任务时须同步制定测试方案。
- **验收标准具体化**: 待办条目须写清执行范围、非目标、可验证验收标准与回滚边界，禁止模糊口径。
- **设计先行闸门**: 涉及新模块、跨模块边界调整、数据/接口契约重写时，先完成设计文档再进入实现。
- **迭代内新增事项闸门**: 开发中发现的额外事项默认不自动并入当前阶段，须先评估是否属于当前范围或应延期。

## 2. 路线图与待办管理

### 2.1 路线图 (Roadmap)

- `docs/plan/roadmap.md` 维护阶段概览。
- 已完成阶段标注状态，阶段切换前须完成归档。
- 下一阶段在上一阶段归档完成后才开启正式规划。

### 2.2 待办事项 (Todo)

- `docs/plan/todo.md` 仅包含当前阶段具体实施任务。
- 任务状态：`[ ]` 待办 / `[x]` 已完成 / `[-]` 已取消。
- 任务描述包含验收标准。

### 2.3 归档管理

- 阶段完成后，详细内容归档至 `docs/plan/todo-archive.md`。
- 归档保留原始层级结构、状态与验收标准，确保历史可追溯。
- 行数阈值：
  | 文档 | 健康窗口 | 强制分片 |
  |------|---------|---------|
  | `todo.md` | <= 500 行 | > 600 行 |
  | `roadmap.md` | <= 800 行 | > 900 行 |
  | `todo-archive.md` | <= 500 行 | > 700 行 |

## 3. 迭代中途新增事项分流

1. **范围核对**: 先检查是否已在 `todo.md`、`roadmap.md` 当前阶段或 `todo-archive.md` 中。
2. **分类决策**:
   - A 类（当前范围）: 允续执行，补充说明
   - B 类（允许插队）: 仅限阻塞交付、功能回归、高风险安全/合规问题
   - C 类（延期）: 体验优化、非阻塞重构、探索性想法等统一延后
3. **容量控制**: B 类事项进入后若超出 5-6 项，须挪出一项低优先级内容至 `backlog.md`。

## 4. 阶段归档流程

1. 确认当前阶段已归档 — `todo.md` 已清理、`todo-archive.md` 已追加
2. 确认回归/验证证据可追溯
3. 同步 `roadmap.md` 阶段状态
4. `lint` / `typecheck` / 定向测试结论可查
